# Top-100 promise intake

Alex requested broader coin coverage with mostly automated research. Codex owns
intake automation; Muse owns the reviewed verdict inputs already assigned in
the hearts-verdict contract. New candidates do not become published ratings.

## First slice

`app/scripts/collect-promise-intake.ts` uses the existing CoinGecko adapter for
one market-cap-ordered batch of 100 assets. It stores the response, capture date,
source URL, digest and candidate identities under `db/research/intake/`.
It reuses the latest capture for 24 hours and retains old captures. Failure
does not replace existing data with an empty result. Partial coverage is explicit.

Run from `app`: `node --import tsx scripts/collect-promise-intake.ts`.

Scope assumption pending Alex's preference: CoinGecko's standard market-cap
universe, including stablecoins it returns. This is not 100 distinct issuers.
Use canonical provider IDs; never equate tokens because their tickers match.
Provider defaults may exclude rehypothecated tokens. Related-token and issuer
grouping need identity review before promises are assigned. Reference:
[CoinGecko markets endpoint](https://docs.coingecko.com/reference/coins-markets).

Existing mappings mean we recognize the asset, not that its research is complete.
Discovery captures are separate from human review files; refreshing membership
must not overwrite research, drop failed promises or remove former constituents.
The CLI does not crawl arbitrary sites, invoke a model, modify Supabase, create
scored promises or publish ratings. No new paid service or scheduler is added.

## Ordered follow-up

1. Resolve identities and group wrappers/related tokens without duplicating underlying obligations. Keep missing identities pending.
2. Collect official whitepapers, roadmaps and attributable statements. Save exact locators, dates, bounded excerpts and retrieval provenance. Refresh only changed sources.
3. Extract candidate commitments and fulfillment tests with an agent, deduplicate against stable lineages and separate claim sources from outcome evidence. Version the extraction prompt/model; keep retrieved instructions untrusted.
4. Review exceptions and a sample of routine drafts in the first 100. Prioritize disputed attribution, duplicate obligations, missing evidence, importance assignments and changed verdicts. Measure correction rates before reducing review further.
5. Validate and propose compatible publications through the existing reviewed release path. Pending research is neither a failure nor a fulfilled promise. Do not run the legacy market-score pipeline to create promise verdicts.

The automation budget should go to source retrieval and changes, not repeated
full research on every token. No confidence threshold can substitute for a
source or silently authorize new scoring rules.
